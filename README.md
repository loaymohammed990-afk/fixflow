# FixFlow

نسخة تعليمية عربية لإدارة طلبات صيانة الجوالات واللابتوبات، باستخدام React وJavaScript وCSS وVite.

## التشغيل

يتطلب Node.js بإصدار 22.12 أو أحدث، وnpm.

```sh
npm install
npm run dev
```

افتح العنوان الذي يظهر في الطرفية (عادةً http://127.0.0.1:5173).

```sh
npm run build
npm run preview
```

ينشئ البناء مجلد `dist`. أمر `preview` يعرض ناتج البناء محليًا.

## ما يمكنك تجربته

- لوحة تحكم بعدادات محسوبة من الطلبات وآخر خمسة طلبات.
- النقر على أي إحصائية لفتح الطلبات بتصفيتها المناسبة.
- بحث جزئي باسم العميل أو رقم الطلب أو الجهاز أو الهاتف، مع فلتر الحالة.
- إضافة طلب والتحقق من الحقول، ثم فتح تفاصيله مباشرةً.
- تعديل البيانات دون تغيير رقم الطلب وتاريخ إنشائه، وتحديث حالة الصيانة.
- تأكيد الإلغاء قبل تغيير الحالة؛ الإلغاء لا يحذف الطلب.
- دعم العربية وRTL ولوحة المفاتيح والشاشات الصغيرة.

## حدود النسخة

كل البيانات تمثيلية. التغييرات في ذاكرة React خلال الجلسة فقط: **تحديث الصفحة يعيد البيانات الأولية ويمسح التغييرات**. لا توجد قاعدة بيانات أو API أو تخزين محلي دائم أو مزامنة. استخدم بيانات وهمية عند التجربة.

الحالات الخمس تعليمية ويمكن الانتقال بينها دون قيود. الرقم التسلسلي اختياري. التحقق من الهاتف شكلي: 7–15 رقمًا مع `+` اختياريًا في البداية، مع قبول الأرقام العربية وتحويلها. هذه ليست قاعدة هاتف خاصة بدولة معينة ولا تحققًا من وجود الرقم.

يُحمّل خط IBM Plex Sans Arabic من Google Fonts عند توفر الإنترنت؛ يستخدم التطبيق Tahoma أو Arial عند تعذّر تحميله. الوظائف والبيانات لا تعتمد على اتصال شبكي.

## بنية المشروع

- `src/App.jsx`: المصدر المشترك للطلبات، التنقل المحلي، والإضافة والتحديث.
- `src/data/mockOrders.js`: سبعة طلبات وهمية وقيم الحالات وألوانها المركزية.
- `src/components`: بطاقة الجهاز، شارة الحالة، النموذج المشترك، ونافذة التأكيد.
- `src/pages`: لوحة التحكم، قائمة الطلبات، والتفاصيل.
- `src/styles.css`: التصميم العادي والتجاوب.

## كيف تعمل حالة React؟

```jsx
const [orders, setOrders] = useState(mockOrders);

setOrders((current) =>
  current.map((order) => (order.id === id ? { ...order, status } : order)),
);
```

`useState` يحتفظ بالطلبات أثناء الجلسة. `setOrders` يستقبل القائمة السابقة، و`map()` ينشئ قائمة جديدة يغيّر فيها الطلب المطابق للرقم فقط. تستخدم الشاشات الثلاث القائمة نفسها؛ لذلك تتحدث البطاقة والتفاصيل والإحصائيات معًا. وتستخدم `DeviceCard` الرقم نفسه كـ `key` ثابت عند العرض.

## تجربة القبول اليدوية

شغّل التطبيق ثم نفّذ الخطوات التالية. نتائج فحص التنفيذ موجودة في `VERIFICATION.md`.

1. تأكد أن العربية تظهر صحيحة وRTL، وأن الرئيسية تعرض 7 طلبات: 1 مستلم، 2 قيد الصيانة، 2 جاهزان للتسليم.
2. جرّب روابط الرئيسية والطلبات وإضافة طلب. اضغط إحصائية «جاهز للتسليم»: يجب أن يظهر طلبان، ثم افتح أحدهما وتحقق من رقمه واسم صاحبه.
3. امسح الفلاتر وابحث بجزء من اسم «أحمد»، ثم برقم `1042`. ابحث عن `غيرموجود` وتأكد من رسالة عدم وجود نتائج ثم امسح الفلاتر.
4. افتح الإضافة وحاول الحفظ بحقول فارغة. أدخل اسمًا وهاتفًا `abc123`؛ يجب رفضه برسالة خاصة بالحقل، مع بقاء المدخلات.
5. أكمل النموذج ببيانات وهمية ورقم صالح ونوع جهاز ومشكلة، واترك التسلسلي فارغًا. بعد الإضافة يظهر رقم جديد بحالة «تم الاستلام». ارجع للرئيسية وتأكد من وصول الإجمالي إلى 8 وبقاء الطلبات السابقة.
6. افتح الطلب الجديد وعدّل وصف المشكلة؛ تأكد أن رقمه وتاريخه وبقية الطلبات لم تتغير.
7. غيّر حالته إلى «قيد الصيانة» ثم «جاهز للتسليم». تحقق من اللون البرتقالي ثم الأزرق، ومن تغير الإحصائيات والقائمة. جرّب «تم التسليم» أيضًا.
8. اضغط «إلغاء الطلب»، ثم «تراجع»: يجب أن تبقى الحالة السابقة. كرر مع «تأكيد الإلغاء»: تصبح الحالة «ملغي» بالأحمر دون اختفاء الطلب. جرّب اختيار «ملغي» من القائمة كذلك، وإغلاق التأكيد بمفتاح Escape.
9. صغّر النافذة إلى عرض 390 بكسل وجرّب القائمة والنموذج والتفاصيل؛ لا ينبغي ظهور تمرير أفقي. جرّب التنقل بمفتاح Tab وفتح النافذة وإغلاقها بلوحة المفاتيح.
10. حدّث الصفحة: يجب أن تعود الطلبات السبعة الأولية، ويختفي الطلب الجديد. يظهر تنبيه هذا القيد في كل شاشة.

للتعلّم، غيّر لون `.ready` في ملف CSS، أو نصًا في لوحة التحكم، وشاهد التحديث أثناء تشغيل `npm run dev`.

لم تُضف مكتبة إدارة حالة أو Router أو Backend أو بنية اختبارات ثقيلة؛ كل ما سبق خارج نطاق هذه النسخة.
